# 逐步骤审查

按规则检查模型回复和工具参数。命中规则后，通过 DSH 原生 spawn 创建独立审查子会话；主会话候选保持等待，审查 Agent 可调用工具读取引用文件、核对事实。通过后交付回复并执行候选工具，拒绝后由原会话订正。

- 内置提交说明、Release 正文、精炼表达、结论与证据相称、综合交付五条规则。
- 支持关键词、正则匹配；提示词、审查模型和推理等级可单独配置。
- 候选在待审块中流式展示，审核时切换边框颜色；通过后恢复正常消息，拒绝后在原块展示订正反馈。
- 保存后热更新，后续主模型请求使用新配置。
- 拒绝记录展示候选内容与订正反馈，代码沿用 DSH 原生渲染。

## 安装

生成速度修复依赖宿主按请求保留 chunk 原始采样时间。请先应用并构建 [计时补丁](patches/dsh-0.2.2-rc.5-stream-timing.patch)，重启宿主后加载本版插件；补丁基线和操作见 [补丁说明](patches/README.md)。聊天、轨迹和统计的生成速度采用模型 finish 时间，审核等待保留在步骤墙钟中。

v0.2.3 为预览版，适用于 DSH 0.2.2-rc.5 Web 与 Node.js 24.9 或以上版本。宿主需具备独立审查池和生成计时接口；普通 rc.5 请按[补丁说明](patches/README.md)完成宿主升级，再安装本版插件。安装包见 [GitHub Releases](https://github.com/QuanhuZeYu/dsh-step-review/releases)：

~~~sh
dsh plugin --profile web add https://github.com/QuanhuZeYu/dsh-step-review/releases/download/v0.2.3/dsh-step-review-0.2.3.tgz
~~~

升级前先在插件管理器关闭逐步骤审查插件包。完成宿主补丁构建并重启后，再使用上面的命令安装、重新启用插件并刷新页面。配置入口为 DSH Web 的「插件 → 逐步骤审查」。

## 使用

选择审查 Agent preset 和模型 → 按需编辑规则 → 勾选“启用审查” → 保存并生效。preset 字段复用原生目录，也可直接填写 preset id。

审查默认关闭。插件自动注册默认 preset `step-review-reader`，提供 `read`、`grep`、`glob` 取证工具和结构化裁决工具。自定义 preset 自行定义工具与权限，审查模型由下方模型设置独立指定。审查子会话独立运行，在支持目录分类的宿主中进入单独的“审查”入口，工作子 Agent 列表保留工作任务。新审查使用 review 分类和独立名称前缀；历史身份可确认时自动回填分类。spawn 后主候选等待裁决；超时、故障或达到订正上限时停止当前回合并留下反馈。

「高级设置」可调整单次审查 Agent 的总期限（默认 120000 毫秒）和步骤上限（默认 12）。已有超时覆盖值继续生效。默认值可按需调高；规则条数、匹配模式和提示词不另设容量上限。步骤、并发和订正次数接受安全整数；超时接受 1–2147483647 毫秒，这是 Node.js 计时器的有效范围。“审查并发上限”默认 16，在同一宿主的独立池中计数，与工作 Agent 容量分开。保存后新接纳读取当前容量；调低不会中断已运行审查，名额在释放完成后归还。池满时明确报容量不足。审查输出沿用所选模型的原生设置，取证沿用原生工具行为；插件不再设置输出 token、响应缓冲或累计材料上限。旧配置中的容量字段不再参与运行。

模型与推理等级可按规则覆盖。规则继承模型时沿用全局推理等级；自选模型时使用该模型的提供方默认等级。显式选择“提供方默认”会保留为 `null`，空值沿用继承语义。

Release 规则只审查实际创建或更新正文的发布操作；写草稿、评阅正文、构建、打包和校验附件直接通过。实际发布引用正文文件时才要求读取落盘内容。Release 规则先判断真实工具用途；源码、规则配置、开发探针及代理交接中引用的发布示例属于开发材料。规则覆盖 `gh release create/edit` 和等价 GitHub Releases API 正文写入。正文保留产品变化、兼容性、已知限制与用户校验方法，开发过程汇报留在开发记录。审查 Agent 必须读取 `--notes-file` 等引用；正文不可取证时拒绝。同一候选里先写文件再发布时，应拆成两个步骤，让审查读取已经落盘的发布正文。审查通过后、放行前会复核取证文件版本；变化时停止并要求重新审查。“载入默认规则”会替换当前规则列表，保存后生效。

内置默认规则包括提交说明、Release 正文、精炼表达、结论与证据相称、综合交付。后三项借鉴 [GPT with Taste](https://github.com/NB-Corp/gpt-with-taste) 的行为原则，要求拒绝指出具体问题及实际影响，保留必要事实、失败、限制与原始记录。证据未展示本身不构成拒绝理由。已有配置可在设置中载入默认规则，保留所需自定义内容后保存。

命中规则时，相关回复、工具参数和取证内容会发送给所选审查模型。「提供最近一条用户请求」默认关闭。请根据数据敏感程度选择提供方。

本版需要宿主提供 `createCapacityPool`、`markStreamChunkTime` 和 `streamChunkTime` 接口。配套补丁同时更新聊天、轨迹和统计的生成完成端点。历史记录中已丢失的上游生成时间无法精确还原。
