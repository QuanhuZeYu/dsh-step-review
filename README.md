# 逐步骤审查

按规则检查模型回复和工具参数。命中规则后，通过 DSH 原生 spawn 创建独立审查子会话；主会话候选保持等待，审查 Agent 可调用工具读取引用文件、核对事实。通过后交付回复并执行候选工具，拒绝后由原会话订正。

- 内置提交说明、Release 正文、精炼表达、结论与证据相称、综合交付五条规则。
- 支持关键词、正则匹配；提示词、审查模型和推理等级可单独配置。
- 保存后热更新，后续主模型请求使用新配置。
- 拒绝记录展示候选内容与订正反馈，代码沿用 DSH 原生渲染。

## 安装

适用于 DSH 0.2.2-rc.5 的 Web 界面和 Node.js 24.9 或以上版本。从 [GitHub Releases](https://github.com/QuanhuZeYu/dsh-step-review/releases) 获取已构建的安装包：

~~~sh
dsh plugin --profile web add https://github.com/QuanhuZeYu/dsh-step-review/releases/download/v0.2.0/dsh-step-review-0.2.0.tgz
~~~

安装或升级均可使用上面的命令。安装后在 DSH Web 的「插件 → 逐步骤审查」打开配置。插件加载遵循 DSH 原生热更新流程；若宿主报告需要重启，再按提示处理。

## 使用

选择审查 Agent preset 和模型 → 按需编辑规则 → 勾选“启用审查” → 保存并生效。preset 字段复用原生目录，也可直接填写 preset id。

审查默认关闭。插件自动注册默认 preset `step-review-reader`，提供 `read`、`grep`、`glob` 取证工具和结构化裁决工具。自定义 preset 自行定义工具与权限，审查模型由下方模型设置独立指定。审查子会话独立运行，在支持目录分类的宿主中进入单独的“审查”入口，工作子 Agent 列表保留工作任务。新审查使用 review 分类和独立名称前缀；历史身份可确认时自动回填分类。spawn 后主候选等待裁决；超时、故障或达到订正上限时停止当前回合并留下反馈。

「高级设置」可调整单次审查 Agent 的总期限（默认 120000 毫秒）和步骤上限（默认 12，范围 1–64）。已有超时覆盖值继续生效。`maxReviewTokens` 默认 16384，是审查 Agent 每次模型响应的输出上限；请按提供方支持范围调整。

取证结果超过剩余材料预算时，工具会提示审查 Agent 缩小读取窗口或聚焦搜索；无法完整取证时返回拒绝及订正建议。总期限、步骤和输出上限继续约束整个审查过程。

模型与推理等级可按规则覆盖。规则继承模型时沿用全局推理等级；自选模型时使用该模型的提供方默认等级。显式选择“提供方默认”会保留为 `null`，空值沿用继承语义。

Release 规则先判断真实工具用途；源码、规则配置、开发探针及代理交接中引用的发布示例属于开发材料。规则覆盖 `gh release create/edit`、GitHub Releases API 正文和明显的 Release 正文文件写入。正文保留产品变化、兼容性、已知限制与用户校验方法，开发过程汇报留在开发记录。审查 Agent 必须读取 `--notes-file` 等引用；正文不可取证时拒绝。同一候选里先写文件再发布时，应拆成两个步骤，让审查读取已经落盘的发布正文。审查通过后、放行前会复核取证文件版本；变化时停止并要求重新审查。“载入默认规则”会替换当前规则列表，保存后生效。

内置默认规则包括提交说明、Release 正文、精炼表达、结论与证据相称、综合交付。后三项借鉴 [GPT with Taste](https://github.com/NB-Corp/gpt-with-taste) 的行为原则，要求拒绝指出具体问题及实际影响，保留必要事实、失败、限制与原始记录。证据未展示本身不构成拒绝理由。已有配置可在设置中载入默认规则，保留所需自定义内容后保存。

命中规则时，相关回复、工具参数和取证内容会发送给所选审查模型。「提供最近一条用户请求」默认关闭。请根据数据敏感程度选择提供方。

独立“审查”入口需要宿主支持目录分类；普通 DSH 0.2.2-rc.5 需先应用[配套宿主补丁](https://github.com/QuanhuZeYu/dsh-step-review/tree/main/patches)并重新构建。仅升级本插件可获得原生审查与新规则，目录分组由宿主提供。
