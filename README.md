# 逐步骤审查

按规则检查模型回复和工具参数。命中规则后，通过 DSH 公开 Agent 工厂在隔离运行时创建临时审查 Agent；主会话候选保持等待，审查 Agent 可调用工具读取引用文件、核对事实。通过后交付回复并执行候选工具，拒绝后由原会话订正。

- 内置提交说明、Release 正文、无必要备份、精炼表达、结论与证据相称、综合交付六条规则。
- 支持关键词、正则匹配；提示词、审查模型和推理等级可单独配置。
- 同一轮、同一步的待审候选流式展示。通过后由正常消息接管，拒绝的候选和对应的订正反馈仍可展开回看。
- 保存后热更新，后续主模型请求使用新配置。
- 拒绝记录展示候选内容与订正反馈，代码沿用 DSH 原生渲染。

## 安装

本版采用纯插件实现，适配未修改的 DSH 0.2.2-rc.5。审查目录、并发控制和生成／审核计时均由插件提供，安装无需宿主源码补丁。原生聊天、轨迹和统计保持宿主原有口径。

适用于 DSH 0.2.2-rc.5 的 Web 界面和 Node.js 24.9 或以上版本。

~~~sh
dsh plugin --profile web add https://github.com/QuanhuZeYu/dsh-step-review/releases/download/v0.2.4/dsh-step-review-0.2.4.tgz
~~~

安装后，在 DSH Web 的「插件 → 逐步骤审查」打开配置。若宿主提示需要重启，请按提示处理。

## 使用

将审查 Agent preset 设为 `step-review-reader`，选择模型，按需编辑规则并启用审查。

审查默认关闭。插件自动注册默认 preset `step-review-reader`，提供 `read`、`grep`、`glob` 取证工具和结构化裁决工具。隔离审查使用内置 `step-review-reader` preset，审查模型独立配置。新审查运行在独立作用域，详情附属于主会话，左侧工作区不会新增独立审查会话。在主会话顶部打开“审查目录”，可查看或删除单条新记录，也可清理当前会话的通过项。删除详情会保留主对话中的订正反馈。此前写入的独立审查会话仍可从历史记录打开。审查不注册为原生工作子 Agent。主候选等待裁决；临时模型故障会有限重试，容量满时排队并允许取消。首条明确拒绝即交回原会话订正。配置错误、预算耗尽或无法取得有效裁决时，当前回合保留具体错误码、规则、模型、失败阶段与原因。预览、详情保存和资源回收故障单独告警，不改变已取得的裁决。关闭开关立即独立保存，不要求先修复其他草稿。

「高级设置」可调整候选审查总期限（默认 120000 毫秒）和单个审查 Agent 的步骤上限（默认 128）。总期限覆盖匹配、容量等待、全部命中规则及取证复核。已有的超时和步骤上限配置继续生效。默认值可按需调高；规则条数、匹配模式和提示词不另设容量上限。步骤、并发和订正次数接受安全整数；超时接受 1–2147483647 毫秒，这是 Node.js 计时器的有效范围。“审查并发上限”默认 16，在同一宿主的插件协调器中计数，与工作 Agent 容量分开。保存后新接纳读取当前容量；调低不会中断已运行审查，名额在裁决确定或取消后归还，底层清理在后台进行。池满时按先到先得排队，并受候选期限约束。审查输出沿用所选模型的原生设置，取证沿用原生工具行为；插件不再设置输出 token、响应缓冲或累计材料上限。旧配置中的容量字段不再参与运行。

模型与推理等级可按规则覆盖。规则继承模型时沿用全局推理等级；自选模型时使用该模型的提供方默认等级。显式选择“提供方默认”会保留为 `null`，空值沿用继承语义。

Release 规则只审查实际创建或更新正文的发布操作；写草稿、评阅正文、构建、打包和校验附件直接通过。实际发布引用正文文件时才要求读取落盘内容。Release 规则先判断真实工具用途；源码、规则配置、开发探针及代理交接中引用的发布示例属于开发材料。规则覆盖 `gh release create/edit` 和等价 GitHub Releases API 正文写入。正文保留产品变化、兼容性、已知限制与用户校验方法，开发过程汇报留在开发记录。审查 Agent 必须读取 `--notes-file` 等引用；正文不可取证时拒绝。同一候选里先写文件再发布时，应拆成两个步骤，让审查读取已经落盘的发布正文。高级设置中的“取证文件变化时中止”默认关闭；开启后，审查通过、放行前会复核取证文件版本，变化或消失时重新审查一次，持续变化才停止并说明具体原因。关闭时按审查读取的证据与裁决继续。“载入默认规则”会替换当前规则列表，保存后生效。

“无必要备份”规则检查文本计划与工具参数中附带的预防性备份，抑制普通可逆编辑、已有可靠恢复来源时额外创建副本。用户明确要求的备份、备份任务与有具体必要性的恢复副本可通过；讨论、读取、恢复和清理既有备份不受限制。已有配置添加 `unnecessary-backup` 后生效，也可在备份前向主模型明确说明是否需要备份。

内置默认规则还包括提交说明、Release 正文、精炼表达、结论与证据相称、综合交付。后三项借鉴 [GPT with Taste](https://github.com/NB-Corp/gpt-with-taste) 的行为原则，要求拒绝指出具体问题及实际影响，保留必要事实、失败、限制与原始记录。证据未展示本身不构成拒绝理由。已有配置可在设置中载入默认规则，保留所需自定义内容后保存。

命中规则时，相关回复、工具参数和取证内容会发送给所选审查模型。「提供最近一条用户请求」默认关闭。请根据数据敏感程度选择提供方。

插件计时行将生成时间（首个有效增量至模型响应完成）与审核等待（模型完成至候选放行）分开显示。仅在有效时间采样与输出 token 用量齐全时显示生成速度；缺失采样不会以消息发布时间补算。审查结束后回收临时 Agent，详情按独立记录持久保存。
