# 开发

更新运行产物前先通过插件管理器关闭审查插件包，确认卸载后同步完整产物。部署验收须在目标长期进程中创建审查 Agent，以合成材料完成只读取证与结构化裁决，并核对工具隔离和设置，验证完成后恢复审查关口。避免活动审查随热载卸载而中断当前回合。

统计速度校正包含在同一客户端产物中，构建复用 `@deepseek-ai/dsh-experimental-client-ui-stats@0.2.2-rc.5` 的浏览器工厂。插件包激活时替换原统计入口，卸载时恢复。验收须停用独立 `dsh-stats-speed`，核对单包的统计速度、分页和卸载恢复。

目标环境：未修改的 DSH 0.2.2-rc.5、Node >=24.9.0。源码构建使用已构建的原版 DSH checkout，复用其原生客户端组件与类型。审查使用公开 preset 装配、工作目录和委派权限接口；结构化输出注册在审查 Agent 私有作用域。

~~~text
node scripts/link-dsh.mjs /path/to/deepseek-harness
npm run typecheck
npm run build
~~~

外置插件在独立终端运行 `npm run watch:host` 与 `npm run watch:client`。Host 的 hmr roots 加入本插件真实 lib 目录，并保留原有 roots。客户端 HMR 还需同一 DSH checkout 运行 `dev:web`；其他 Web 变更按宿主构建与刷新流程验证。

插件通过公开 `conversation.view` 插槽注册会话顶部的“审查目录”标签，新详情由通过连接鉴权的接口读取和清理，使用 `storageDomain` 的逐条文件布局。历史独立审查会话仍通过标准会话事件源及 `uiWorkspace.openSession` 导航。

响应关口先缓冲主候选，再为每条命中规则在独立 Cordis 根通过公开 Agent 工厂创建临时审查 Agent。聊天投影以轮次与步骤归并预览和订正注入，新的 previewId 开始一次尝试，先前候选与反馈收入默认收起的历史。通过后由原生消息接管，已拒绝的候选和订正反馈仍可展开回看。活动或历史审查可从相关卡片打开，新归档也可在“审查目录”中查看。归并仅作用于显示，原始日志与模型注入完整保留。审查可调用 preset 工具取证，主候选等待审查结束。默认 `step-review-reader` 提供只读工具；隔离运行时使用内置 preset 并执行宿主工具权限检查。审查会话须跳过本插件关口以避免递归，主会话取消、插件卸载和总期限触发时应终止对应审查。

`maxConcurrentReviews` 默认 16。插件共享协调器维护独立名额，多处挂载采用有效配置中的最小容量。容量满时进入可取消的 FIFO 队列，排队共用候选总期限。裁决确定或取消后先释放名额，独立 Agent 取消和回收在后台进行；晚到创建结果仍回收，已取消运行禁止新工具。协调器卸载按世代检查，旧卸载不删除新挂载接管的状态。审查直接使用公开 Agent 工厂，不经过原生 SubagentManager 或工作容量池。历史会话可读取，活动审查不加入原生子 Agent 恢复。

`reviewerPreset` 默认 `step-review-reader`；`maxReviewSteps` 默认 128。`timeoutMs` 默认 120000。显式配置继续生效。插件配置不再限制规则数、模式数和字符串长度；步骤、并发和订正次数仅校验安全整数及其下界。超时范围 1–2147483647 毫秒，与 Node.js 计时器一致，前后端共用边界。审查 Agent 显式清除父 Agent 的 `maxTokens` 覆盖，让所选模型按原生设置解析输出上限。插件不累计限制响应字节、初始材料与取证字符，`stopOnEvidenceChange` 默认 `false`，旧配置未填写时也关闭；开启后在放行前复核成功取证的文件目标与版本，漂移后在候选总期限内重新审查一次，持续漂移时以具体错误码停止。关闭时仍保留正常取证与裁决，后续文件变化不单独触发中止。该字段随主请求开始时的配置快照固定。模型覆盖和推理等级三态沿用既有契约：空值继承，`null` 使用提供方默认，字符串指定等级。

配置页读取原生 settingsSchema 与 ConfigForms describe 镜像，按修订号原子保存实际变化字段；冲突时保留草稿。preset 只接纳内置 `step-review-reader`。关闭开关只原子提交 `enabled=false`，跳过其他草稿校验；普通保存继续校验启用规则。配置快照在下一次主模型请求读取；仅刷新网页不能替换 Host 模块。

默认 Release 规则检查发布正文及其引用文件。取证失败必须拒绝；先写正文再发布须分成两步。规则只输出局部订正建议，主会话执行修改。审查 Agent 通过插件在独立作用域注册的 `structured_output` 工具提交裁决；仅成功的工具结果提交状态，PTC 内层调用还须等外层成功：

~~~json
{"decision":"reject","reason":"具体问题","suggestions":["局部修改建议"]}
~~~

通过时使用 `decision=pass`。取证义务由本条规则决定：文本结论规则按给定材料判断具体矛盾，未附构建或运行记录不触发全盘追证；Release 等明确要求核验实际文件的规则仍须读取对应材料。步骤额度包含最终结构化裁决。

瞬态模型错误按单步骤最多重试两次，分别退避 200/400 毫秒；认证和配置错误不重试，成功响应清除此前失败状态。主关口按请求对象去重，多个实例不重复审查。首条拒绝立即反馈。必要停止使用 `ReviewError extends LlmError`，保留具体 code、阶段及脱敏的原因链。

预览失败只停用展示。详情快照后台保存，保存等待和回收均不阻塞候选、取消及插件卸载；未落盘记录保留最近 128 条内存缓存供查看，持久化记录不受该缓存数量限制。域打开失败后下次访问重试，读取存储等待有独立期限。
